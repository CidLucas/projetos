## 3. Descobertas técnicas da sessão

### 3.1 WhatsApp (Twilio) — por que as tools "nunca funcionaram"
- **Código da lib está correto** (`send_whatsapp` usa `whatsapp:` prefix + Messages API) — o problema é **configuração/conta**, não a lib:
  - **Sandbox:** destinatário precisa **opt-in** (mandar a mensagem de join p/ o número sandbox) antes de receber
  - **Mensagens business-initiated exigem template aprovado** (`content_sid`) — body livre só na janela de 24h após o cliente iniciar
  - `from` precisa ser `whatsapp:+<número>` (sandbox `+14155238886` ou número real com WABA)
  - Quickstart oficial: https://www.twilio.com/docs/whatsapp/quickstart
- **Passo a passo de conta** (Twilio Console): Messaging → WhatsApp → Try out WhatsApp → scan QR/send join → usar o número do sandbox como From + destinatário verificado como To. Em produção: registrar número real + WABA (requer aprovação da Meta).
- **Webhook:** configurar URL no Console (WhatsApp → webhook), retornar TwiML `<Response><Message>`; validar `X-Twilio-Signature` (já implementado em `webhook.py` da lib). Timeout ~5s → reply imediato + processamento assíncrono.

### 3.2 Multi-tenant no Neon — padrão memory_api (espelhado na lib)
- Schema próprio (`agent_runtime`), migrations SQL numeradas `NNNN_nome.sql` com checksum (aplicada = imutável), aplicador `make migrate`
- Control plane: `tenants`, `users`, `memberships` (owner/admin/member), `scope_grants`
- **Regra F-20:** identidade vem SÓ do token (custom claims `tenant_id`/`role`/`scopes` via hook Supabase) → `Principal` frozen dataclass em ContextVar; argumento de roteamento nem existe no schema das tools
- `IdentityAdapter` Protocol (Claims → ControlPlane) + `AuthGate` middleware
- **Agno não tem `tenant_id` nativo** no PostgresDb → `TenantPostgresDb` com coluna dedicada + filtro em toda query (recusadas: `user_id` composto e `metadata` JSON)

### 3.3 Agno + MCP HTTP (pitfall resolvido)
- `MCPTools` do Agno **não aceita URL HTTP** nativa — solução debugada no agente-bloquo: `streamablehttp_client` + `ClientSession` + `MCPTools(session=...)`, conexão por request com `async with` no mesmo task (evita async-gen pendurado)
- Agente stateless (recriado por request), sessão no DB via `session_id` — nada em memória

### 3.4 Reuso do monorepo (quase tudo pronto)
- **WhatsApp:** `blu_twilio_client` pronta + tools `send_whatsapp_message`/`send_whatsapp_batch`/`check_whatsapp_status` no tool_pool (já usadas pelo Blu)
- **Google:** `GoogleDocsClient` **já existe** (create/read/append/replace/list) — só expor tool; `query_calendar` já existe
- **Polp (Open Finance):** backend_api faz connect/sync/webhook; routines FIN-01 (saldos) e FIN-02 (gastos por categoria); tabelas `polp_accounts/transactions/bills/integrations/webhook_events`; webhook `transaction/created` no tool_pool
- **Infra:** blu_llm_service (tiers), blu_auth (Supabase), blu_lgpd (obrigatória p/ dados financeiros)
